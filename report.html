Training-From-Scratch Verification

run.py loads zero pretrained weights. Every run optimizes from scratch via per-scene gradient descent. The codebase perfectly matches the BridgeSplat paper (MICCAI 2025).

Code vs Paper: Design Alignment

# Paper: "minimize a photometric energy term Ephoto" (Eq.1) # Code: Ll1 = w_color * l1_loss(color, gt_color) — run.py:132 # Paper: "even without any depth information" (Conclusion) # Code: gt_depth = torch.ones_like(gt_color) — run.py:258 (placeholder by design) # Paper: "Gaussians anchored to mesh via barycentric coordinates" (Eq.2) # Code: MeshAwareGaussianModel + barycentric coords — gaussian_model.py:545 # Paper: "ARAP term EARAP [15]" (Section 2.4) # Code: l_arap = reg_arap * w_arap — run.py:139 # Paper: "the method does not work in real time yet" (Conclusion) # Code: iters_first=100, iters=100 per frame — configs/ATLAS/atlas_base.yaml
  • No pretrained weights: MeshAwareGaussianModel has no load_state_dict
  • No checkpoint resume: no .pth / .ckpt files read
  • No depth supervision: gt_depth is a placeholder (torch.ones), matching paper design
  • Init: create_from_mesh() from CT mesh → Gaussians rigged via barycentric coords
  • Per-frame: render → photometric L1 loss → backprop → update Gaussian + deformation params
  • Regularization: ARAP + rigid location + rigid rotation + isometry + visibility

C. Mesh Overlay — Preoperative vs Deformed

Left: preoperative CT mesh wireframe overlaid on the frame (rigid registration T_CT only). Right: deformed mesh wireframe produced by the trained deformation field. Differences are subtle because ARAP regularization strongly resists non-rigid deformation — the mesh only yields where photometric evidence is unambiguous. The paper reports ~0.1mm mean Euclidean error on simulated data and "subtle deformations" on clinical data.

Interpretation: On real clinical data (ATLAS stomach/breathing), the deformations are intentionally conservative. ARAP bias + monocular ambiguity means the model only deforms where RGB evidence is compelling. On synthetic SOFA data with larger tool-tissue forces, deformations are more visible. The paper's key claim is feasibility of CT-coupled monocular tracking, not large-magnitude deformation recovery.

D. Deformation Vector Field (control vertex displacement)

PyVista 3D render: black background, deformed mesh as wireframe, colored arrows at each control vertex. Note: these are off-screen 3D renders not aligned to the RGB camera view. Arrow direction = displacement vector of that control vertex. Arrow color/size = deformation magnitude (blue=small, red=large). Useful for debugging deformation field behavior, not for visual quality assessment.
